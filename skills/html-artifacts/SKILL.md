# HTML artifacts

Read [the HTML artifact policy](references/HTML.md) in full before creating or
changing the artifact.

## Workflow

1. Establish the artifact's purpose, audience, host, delivery contract, and
   project conventions
2. Inspect the existing source and rendered result before making a change
3. Build the smallest semantic, accessible implementation that preserves the
   important content and relationships
4. Render and exercise the final artifact in its delivery context
5. Report the final path, verification, consequential assumptions, and known
   limitations

Treat rendered output as the source of truth for visual and interaction QA.
